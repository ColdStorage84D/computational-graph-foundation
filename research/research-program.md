# Research Program

Use this page to define the research program that supports CGF.

The project should be self-contained. Research notes should be written as
CGF-native material before becoming public docs.

## Initial Threads

- Substrate primitives and their minimum useful records.
- Action-Native Computation as the derivative framing for computation as
  constrained graph-state evolution.
- First-principles derivation from action to operator, evolution, readout, and
  validation.
- Geometric multimodal representation as graph, metric, symmetry, topology,
  dynamics, and information structure.
- Higher-dimensional graphs and topological domains for subjects with cells,
  boundaries, fluxes, loops, and higher-order interactions.
- CellComplexView as the narrow Substrate surface for cell, boundary, region,
  and episode support.
- Attractor Diagnostics as a Substrate research thread for dynamical regimes,
  recurrence, drift, and escape warnings.
- Topological rigidity as a Substrate extension.
- Execution graph, graph brain/spine, subgraph capsules, and graph runtime
  memory as Architecture research threads for systems that act.
- Anchor / Lens / Promise, Visual Media Encoding, Hierarchical Execution
  Cycles, Offline Replay / Dream Cycles, Belief State, Bayesian Filtering,
  Cognitive Map Memory, Engram / Spatial Memory, and Subgraph Role Registry as
  Architecture research threads for operating around declared subjects.
- Provisional Graph Growth as an Architecture research thread for bounded
  graph adaptation, provisional capsules, candidate variants, promotion gates,
  and rollback.
- Granular Analysis as an Architecture research thread for multi-lens,
  multi-proposer, traceable outcome analysis.
- Multimodal Outcome Stack as an Architecture research thread for evidence
  records, typed graph records, feature views, processor routes, proposals,
  review, and traceable outcomes.
- Signal Review as an Architecture research thread for signal views,
  route-specific processors, review / abstain / fallback behavior, and
  traceable signal decisions.
- Reusable Architecture framework cards as the place where bot, medical image analysis,
  security, cache, sensor, routing, evidence, and review concepts are separated
  from application examples.
- Path-conditioned and path-gated operators as first-class Architecture
  patterns inside the execution graph for explicit path influence and path
  authority.
- Promotion rules: when a research idea becomes a named extension,
  Architecture framework card, Architecture pattern, or Application pattern.
- Evaluation discipline for examples and future implementations.
- Value-over-baseline and recipe-grounded eval discipline for deciding when a
  concept deserves stronger public positioning.

## Promotion Rule

Research ideas become public extensions, Architecture patterns, or Application
patterns only after they have:

- a one-sentence definition;
- a parent layer;
- a failure mode they solve;
- a minimal primitive shape;
- at least one small example;
- a maturity label.

## Public Safety

Do not move private data, generated challenge outputs, or unclear-license
material into public docs. Publish promoted ideas as clean CGF-native material.

Do not promote public mathematical, scientific, or software concepts
without a reference pass. Internal research may be included, but it must be
labeled as internal when it is not published public prior art.
